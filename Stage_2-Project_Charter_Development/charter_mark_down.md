# Move Right - Project Charter (Stage 2)

## Project Objectives

**Purpose:** Move Right is a web application created to serve as a training tool assisted with computer vision, data capture and processing. The project exists to provide users with metric data for movement analysis, giving consumers the satisfaction and confirmation to know that they are exercising correctly through empirical feedback.

**SMART Objectives:**

1. **Achieve 90% accuracy in exercise form detection within 6 months** - Develop and refine computer vision algorithms to consistently identify correct vs. incorrect exercise form across our target exercise modalities by project completion.

2. **Process movement analysis for 5+ different user body types by project completion** - Ensure the application works effectively for individuals of varying physiological backgrounds, heights, and body compositions during the final testing phase.

**Success Criteria:**
- The data is obtained consistently upon a single user
- The data obtained and feedback given works for many individuals of varying backgrounds  
- Feedback output is provided correctly on all possible scenarios (correct and incorrect form)

## Scope

### In Scope
- Single training modality
- Single hardware platform
- Simple machine learning model
- Universal audience compatibility

### Out of Scope  
- Large exercise variety
- Multiple training disciplines
- Exercise progressions and regressions

## Risks and Mitigation Strategies

| Risk | Mitigation Strategy |
|------|-------------------|
| Large abundance of concepts to learn on a limited timeframe | Budget (time) planning and management strategies |
| Ineffective software dependencies, leading to tech stack changes | Constant research in packages and use cases for solid references |
| Inconsistent server side logic, resulting in poor application quality | Intense testing periods and keen data observation |
| Absence of direction due to ambiguous or vague project goals | Frequent scrum meetings for daily and weekly decision making, daily Trello board goals for documenting progress |

## High-Level Project Plan

### Phase 1 - Process of Decision Making (Month 1)
Process of decision making lasting from project inception through resource selection and technical documentation compilation:
- Research into software and hardware tools
- Team meetings to discuss compiled information  
- Decision making for choosing in-scope and out-of-scope items

### Phase 2 - Preparation of Technical Documentation
Technical documentation phase covering app behavior, server side logic, interfacing, entity behavior, packages and dependencies:
- Writing comprehensive technical documentation
- Meetings and scheduling operations using Trello and WhatsApp
- Timeline determination for short and long-term goals

### Phase 3 - Coding  
Programming phase building the complete application:
- **Front End Development:** structure, styling, and scripting
- **Back End Development:** computational logic, entities and classes, API methods and endpoints, database schema

### Phase 4 - Testing and Debugging (Concurrent with Phase 3)
Comprehensive application testing ensuring:
- All pages connect properly
- Server side code loads seamlessly into web pages
- Interface logic is solid
- Real user testing to confirm image processing consistency across multiple users
- Movement feedback validation against certified trainer assessments

### Phase 5 - Project Closure and Demo Preparation
Final project phase including:
- Minor tweaking and final debugging
- Demo day preparation
- Project deliverable finalization
